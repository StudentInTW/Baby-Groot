# 娃娃擺拍測試結果（2026/9/21，第三批俯拍＋口鼻檢查實驗後更新）

資料：`dataset/infant_jpg_without_video/`，**114 張照片、185 隻娃娃**，分三批拍（百貨公司賣場實拍，同一組寢具、同兩隻娃娃，全部開燈）：

| 批次 | 照片 | 娃娃 | 內容 |
|---|---|---|---|
| 第一批 | 64 張（直式，站著手持拍） | 110 隻 | 仰睡、側睡、臉朝下趴睡、雙娃娃各種組合 |
| 第二批 | 29 張（橫式） | 40 隻 | 口鼻被蓋住：被子（很多只露額頭或頭頂）、玩偶、衣領拉起來 |
| 第三批 | 21 張（錄影截圖，**近似天花板俯拍**） | 35 隻 | 各種情境，含 10 張雙娃娃 |

程式：`eval_doll.py`（v3＝RTMO＋YuNet；`--face v4`＝v3＋口鼻檢查）。標註：`doll_labels.csv`（`batch` 欄是批次）。輸出：`outputs/doll_eval/`。
以下數字除非另外註明，都是**找人門檻 0.15**（建議值，理由見 §7）。

## 一句話

- **臉朝下趴睡抓得到**：25/25 全部警示，三批都一樣。
- **口鼻被蓋住仍是主要漏洞**，有兩種：
  1. **身體被被子蓋住 → 姿態模型根本不輸出這個人**（被子蓋住的 45 隻只偵測到 9 隻）。
  2. **只露眼睛的「假臉」**：衣領、玩偶、被子蓋住口鼻時，YuNet 照樣找到臉，系統就判成 OK。
- **床位模式＋時序**解決第 1 種：警示召回 62.1% → **90.2%**（模擬）。Harry 提的「影片一開始一定抓得到，之後消失就代表被蓋住」就是這個的影片版，見 §4。
- **口鼻檢查（v4）在娃娃上解決了大部分第 2 種**（偵測到的危險娃娃警示 86.3% → 95.8%，誤報不變），**但在真實嬰兒照（SyRIP）上誤報從 6.1% 變 16.6%**，原因是娃娃不會張嘴、不戴帽子、臉又大。**所以還不採用，v3 仍是主力**，見 §5。

## 1. 計分單位：每隻娃娃各算一次

計分單位是**每隻娃娃**，不是每張照片。`doll_labels.csv` 每隻娃娃一列：位置（軀幹中心；身體被蓋住時標頭）＋口鼻看不看得到。娃娃的標註點落在哪個人框裡，就算系統偵測到那隻（一對一，取框心最近的）。

警示召回率分兩種：**系統層級**（沒偵測到的娃娃算漏，產品真實表現）和**只算偵測到的**（跟 SyRIP 同算法，可互相比較）。

| 算法（v3） | 結果 |
|---|---|
| 以「整張照片有沒有警示」算 | 61/96（63.5%） |
| 以「每隻娃娃」算 | 82/132（**62.1%**） |

36 張「兩隻都危險」的照片裡，**有 6 張只抓到一隻**（v4 是 7 張）——用整張圖算會被判成對的，漏掉的那隻看不出來。

## 2. 標註標準（已依 Harry 的逐張說明更新）

`label` 記**鏡頭看得到的事實**，`staged` 記**拍攝意圖**：

| 欄位 | 值 | 隻數 |
|---|---|---|
| `label`（口鼻看不看得到） | `ok` 看得到／`partial` 只看得到一部分／`alert` 看不到 | 49／4／132 |
| `staged`（拍攝意圖） | `safe` 安全／`warn` 注意／`danger` 危險 | 49／14／122 |

- 「注意」的娃娃可能口鼻看得到（趴睡、頭擺側邊），也可能看不到（「這個角度看不到口鼻，列為注意」）。看不到的一樣算進警示召回——系統會發「無法確認口鼻，請看一眼」，本來就是要提醒的。
- 依 Harry 的說明改了 19 隻：`IMG_8108/8109/8110`（趴睡側臉＝看得到、側睡後腦勺朝鏡頭＝看不到）、`IMG_8113`（兩隻都看不到）、`warn_right_01`／`warn_top_01`（趴睡那隻這個角度看不到）、`danger_top_06/07` 下方那隻（注意、看不到）、`IMG_8091`、`danger_both_08`、`danger_both_11`（原本標 partial 的 3 隻，Harry 確認口鼻都被蓋住）。
- 現在「安全卻看不到口鼻」「危險卻看得到口鼻」的矛盾是 **0 隻**。
- 不列入計分：放在床外展示架上的娃娃、頭幾乎在畫面外的娃娃（共 7 隻）。系統若偵測到會算成額外偵測。

## 4. 床位模式＋時序（Harry 的建議）

**做法**：安裝時在畫面上框出每個床位。每個床位只要**找不到人、或找到人但看不到口鼻**，就警示「無法確認口鼻，請看一眼」。

**Harry 的補充完全正確**：影片版一開始（托育人員把寶寶放下時）一定抓得到嬰兒，之後如果消失，就代表被被子、玩偶這類東西蓋住了，應該警示。這就是床位模式的時序版，而且比單張照片更可靠。實作時要處理的：

1. **抱走 vs 蓋住**：寶寶被抱起來時床位也會「空掉」。消失前幾秒如果有大人進入這個床位，就判成「被抱走」，不發警示（或只記錄）。
2. **偵測閃爍**：偵測器偶爾漏一幀，要連續 N 秒找不到才警示（`context.md` §8 第 5 項本來就有）。
3. **兩隻被框成一個人**：第三批 `converted_danger_right_01` 兩隻並排、蓋同一條被子，RTMO 框成**一個人**，左邊那隻的真臉讓整個框判成 OK，右邊只露頭頂的那隻就被吃掉了。追蹤上會看到兩個 ID 合併成一個（另一個「消失」→ 警示）；床位模式則要**依位置把臉配給床位**，不要透過人框。
4. **放下時就蓋著**：床位是安裝時框的，就算一開始就沒偵測到，也會發「無法確認口鼻」。

**影片驗證**（2026/9/21，`docs/影片測試結果.md`）：兩支娃娃影片、31 段危險、17 段安全，床位模式危險片段抓到 32% → **84%**，安全片段 0 誤報。影片也測出三個實作細節：要直接在床位範圍依床位方向找臉（身體蓋在被子下時 RTMO 不輸出人）、臉要依位置歸給床位、看得到要持續 1 秒才算數（防閃爍）。

**照片模擬結果**（用人工標註的娃娃位置代替床位）：警示召回 v3 **62.1% → 90.2%**、v4 68.9% → 97.0%；誤報率 12.2%（分母是全部 49 隻口鼻看得到的娃娃）。多出來的誤報是 4 隻口鼻看得到、但沒被偵測到的娃娃（3 隻身體在被子下、1 隻身體被大玩偶壓住）——身體整個被蓋住，提醒看一眼不算過分。

床位模式剩下的漏報**全部是「偵測到了但配到假臉」**（v3 剩 13 隻、v4 剩 4 隻），這就是 §5 要處理的。

## 5. 口鼻檢查（v4）：測了，娃娃上有效，但真實嬰兒上誤報太多

### 做法（`infant_face_v4.py`，不用訓練）

YuNet 除了臉框還輸出 5 個特徵點（雙眼、鼻尖、兩個嘴角）。口鼻被蓋住時它仍會「猜」出位置，只是那裡其實是衣服或被子。所以：把臉依雙眼轉正，拿**眉毛上方**的皮膚當膚色基準，算「鼻尖到嘴下方」那塊有多少比例像這個膚色（Lab 色差 < 15）——低於 0.2 就當成口鼻被蓋住，這張臉不算數。

- 基準取眉毛上方、不取鼻樑：衣領拉到眼睛下緣時，鼻樑本身就被蓋住了。
- 色差要算亮度：娃娃的粉色衣領和膚色色相很接近，差在亮度。
- 門檻 0.2 **只用第 1、2 批決定**（被蓋住的 ≤ 0.04，看得到的最低 0.30），第 3 批當驗證。
- v4 找臉的結果跟 v3 逐一相同（驗證過），差別只在口鼻檢查。

### 娃娃：有效

| | v3 | v4 |
|---|---|---|
| 偵測到的危險娃娃，警示召回 | 82/95（86.3%） | **91/95（95.8%）** |
| 誤報率 | 2/45（4.4%） | 2/45（4.4%） |
| 第三批（沒參與調門檻） | 假臉 4 隻 | 擋下 3 隻，真臉 0 隻被誤擋 |

擋下的是衣領拉到眼睛下緣、玩偶或抱枕蓋住口鼻、被子上方只露眼睛這幾類（另有 2 隻後腦勺被當成臉的，因為基準取到了抱枕，也碰巧擋下）。擋不住的 4 隻：玩偶耳朵蓋住嘴但特徵點落在臉頰皮膚上（`IMG_8132`）、鼻子露出只蓋住嘴（`danger_both_11` #2）、枕頭上的卡通熊臉（整塊顏色一致，`danger_bottom_05` #2）、兩隻被框成一個人（`converted_danger_right_01`，見 §4）。

### SyRIP 700 張真實嬰兒：誤報太多

| | v3 | v4 |
|---|---|---|
| 誤報率（人工重標） | 35/571（**6.1%**） | 95/571（**16.6%**） |
| 口鼻看不到 → 警示 | 71/72 | 71/72 |

v4 在 SyRIP 多了 63 個警示，但**一個原本漏掉的都沒多抓到**（SyRIP 口鼻看不到的嬰兒，v3 本來就幾乎全抓到了）。63 個裡有 49 張不在當初的重標名單，程式暫時當成「看得到」；我逐張看過，絕大多數確實是誤報，只有少數是真的該警示（嘴裡含奶嘴、手蓋住臉）。原因都是娃娃身上沒有的情況：

| 原因 | 例子 |
|---|---|
| **臉太小**：一半以上雙眼距離 < 20 像素（SyRIP 照片約 640px），取樣只有幾個像素 | 放大後整張臉是一團糊 |
| **哭、笑時張開的嘴**：嘴巴裡面是暗紅色，不像皮膚 | 娃娃的嘴永遠閉著 |
| **帽子、髮帶、墨鏡、瀏海**：「眉毛上方」取到的是配件或頭髮 | 娃娃是光頭、沒戴東西 |
| **側臉**：下半臉那塊落到背景上 | |

只在臉夠大時才檢查也救不回來：限定雙眼距離 ≥ 20 像素，63 個新增警示還剩 30 個（誤報率仍約 10–11%）。而且把娃娃照縮到 1280px（接近 1080p 攝影機）時，v4 已經開始把看得到的臉誤擋（`warn_bottom_01` #1，誤報 6.7% → 8.9%）。

### 結論

- **這個方向是對的**：娃娃上證明了「假臉」大多是「只露眼睛、口鼻被蓋住」，檢查口鼻區域可以擋掉大部分。
- **但現在的做法太依賴娃娃的特性**（閉嘴、光頭、臉大），不能直接用在真實嬰兒上。**v3 維持主力，v4 留著當實驗版**（`--face v4`）。
- **已改良（2026/9/23，改 `infant_face_v4.mouth_skin_ratio`）**：(1) 只看鼻子和人中、避開嘴巴（避開張嘴的暗色嘴腔）；(2) 臉太小（眼距 < 22px）不檢查（回傳 1.0＝當看得到）。結果：**SyRIP 真實嬰兒誤報（重標）16.6% → 10.9%、召回維持 98.6%**；娃娃「只露眼睛/衣領/玩偶/棉被」的假臉照樣全抓到。連帶 v5 誤報 14.7% → 9.3%。仍比 v3 的 6.1% 高一點（口鼻膚色還是會拒絕部分真實正臉：叼奶嘴、手靠近嘴、陰影），可再收但收益遞減。`eval_syrip.py` 已加 split 欄、`score_relabel.py` 已能拆「躺姿/validate100」報——**調參用 train600、報數字用 validate100**（別拿重標結果調）。
- 優先順序上，**床位模式＋時序（§4）的效益大得多**（62.1% → 90.2%，而且不增加 SyRIP 誤報），應該先做。影片版的「連續幾幀才算數」本身也能擋掉一部分閃爍的假臉。

## 6. 失敗模式（標註圖在 `outputs/doll_eval/vis*/`）

### A. 身體被蓋住 → 姿態模型沒輸出這個人（最大宗）

沒偵測到的 42 隻裡，29 隻是 RTMO 完全沒輸出，**13 隻是有框到、但「可見身體關鍵點 < 3 個」被當雜訊濾掉**（其中 8 隻在第三批：俯拍時身體在被子下，只剩頭）。門檻降到 0.1 也一樣（跟 0.15 相同）。例子：`alert_blanket/IMG_8144.jpg` 兩隻只露頭頂，畫面中唯一被偵測成人的是背景的服飾人偶。

→ 床位模式裡，**床位範圍內「只有頭」的偵測也應該算數**：雜訊過濾器原本是為了擋掉畫面裡大人的手，在床位裡可以放寬。

### B. 假臉（偵測到但沒警示）

v3 有 13 隻：只露眼睛（衣領、玩偶、被子蓋住口鼻）9 隻，後腦勺或側臉 2 隻，枕頭卡通臉 1 隻，兩隻被框成一個人 1 隻。v4 擋下其中 9 隻（見 §5）。

### C. 兩隻被框成一個人

`converted_danger_right_01`，見 §4 第 3 點。

### D. 側臉找不到 → 誤報

`ok_side/IMG_8060`、`IMG_8063`：側躺、口鼻看得到，但沒找到臉。誤報全部集中在側睡（2/9），仰睡是 0/32。

## 7. 調參實驗

| 設定 | 偵測率 | 警示召回（系統層級） | 誤報率 | 額外警示／張 |
|---|---|---|---|---|
| 預設（找人 0.3） | 67.0% | 51.5% | 4.8% | 0.99 |
| **找人 0.15** | **77.3%** | **62.1%** | **4.4%** | 1.94 |

- **找人門檻 0.15 仍然建議**：召回 +10.6 個百分點、誤報率不動。第二批時試過 0.1，跟 0.15 完全相同。
- 提高人臉門檻（0.85）不是解法：第二批時試過，假臉全擋掉但誤報率變 29.7%。
- **代價**：每張多出的「沒配到臉、會跳警示」的人框（背景客人、服飾人偶、展示架上的娃娃），門檻 0.15 時每張 1.94 個。上面的誤報率只算標註過的娃娃、不含這些。**床位模式同時解決這個問題**——只監測床位裡的人。

## 8. 暗光、灰階（IR）與解析度（**模擬**，不是實拍）

賣場是別人的營業場所、有其他客人經過，不能關燈拍。這裡用程式把亮度壓下去模擬（`degrade.dim_image`），數字先當參考；要驗證，改在自己家裡或辦公室用同一組娃娃補拍，或留到 Stage II 用實機在真實午睡室測。

「×0.3」是**線性光量**剩 30%（先把像素轉回線性亮度再乘），換成畫面的像素值大約只暗到 58%，雜訊也很小——比真的暗室樂觀：真的攝影機在暗處會自動拉高增益，雜訊大很多。

| 設定（找人 0.15） | v3 召回 | v3 誤報 | v4 召回 | v4 誤報 | 床位模式 v3（召回／誤報） |
|---|---|---|---|---|---|
| 原圖（開燈） | 62.1% | 4.4% | 68.9% | 4.4% | 90.2%／12.2% |
| 長邊縮到 1280px | 63.6% | 6.7% | 69.7% | 8.9% | 90.2%／14.3% |
| 亮度 ×0.3 | 65.2% | 15.2% | 67.4% | 17.4% | 94.7%／20.4% |
| **灰階（模擬 IR 夜視）** | 59.1% | **28.9%** | 59.1% | 28.9% | 98.5%／34.7% |
| 灰階＋亮度 ×0.3（補光不夠的 IR） | 61.4% | **38.1%** | 61.4% | 40.5% | 97.7%／46.9% |

（灰階兩列是 2026/9/29 補測，`--gray`，處理方式見 `degrade.py`；同一天用現在的程式重跑原圖、亮度 ×0.3，數字跟上表完全相同。四種條件的同一幀對照圖：`outputs/degrade_examples/IMG_8116_conditions.jpg`，自己拍的娃娃，可放簡報。）

- **灰階比變暗更傷**：只去掉顏色、亮度不變，誤報 4.4% → 28.9%（仰睡 0/32 → 6/32、側睡 2/9 → 6/9），全部是「沒找到臉」。原因不是分數整體往下掉——口鼻看得到的 44 隻，灰階減彩色的最高臉分數中位數只有 −0.03——而是**彩色時就在門檻邊緣的臉（0.71–0.86，多半是畫面裡偏小或偏側的臉）在灰階下整張掉光（0–0.4）**，被整張圖 0.7／頭部 0.8 的門檻擋掉。最高分 ≥ 0.8 的娃娃：彩色 40/44 → 灰階 30/44。例：`ok_supine/IMG_8052` 正面仰睡 0.86 → 0.37、`ok_side/IMG_8064` 側睡 0.84 → 0。灰階下娃娃的臉跟粉色衣服、白床單對比變很弱。
- **姿態模型也受影響**：偵測率 77.3% → 69.2%，主要是趴睡（98.6% → 88.7%）。
- **v4 口鼻膚色檢查在灰階下完全失效**：v4 跟 v3 結果一模一樣——彩色時 v3 被 13 隻假臉騙、v4 擋下 9 隻；灰階下 v4 一隻都沒擋。檢查用的是 Lab 色差，灰階只剩亮度差，布料跟皮膚亮度差不多就過關。**IR 模式要另外設計口鼻遮蔽的判斷**，不能沿用膚色。
- **多出來的是誤報、不是漏報**：召回大致持平（62.1% → 59.1%／61.4%，掉的是姿態模型沒找到的趴睡娃娃），床位模式召回反而更高（98.5%）——灰階讓系統「多叫」而不是「漏叫」，安全方向對，但誤報會讓托育人員不信任。

- **解析度大致不是問題**：縮到 1280px（約 1080p），召回不變、誤報多 1 隻（側睡找不到臉）。第二批時測過 640px，誤報明顯上升（21.6%）。
- **暗光是問題**：亮度剩 30% 時誤報率 4.4% → 15.2%，幾乎全在側睡（9 隻側睡裡 5 隻找不到臉）。第二批時測過 ×0.1，誤報 32.4%。實機一定會遇到——硬體面先規劃紅外線補光／IR 攝影機，放進簡報的「硬體架構」段。

## 9. 資料還缺什麼

1. **影片**：`IMG_8116`、`IMG_8150`、`IMG_8115` 都測完了（`docs/影片測試結果.md`）；**6 分鐘的正常睡姿影片 `IMG_8184` 也測完（就是這裡一直缺的誤報樣本）**——結論：正面仰睡 0 誤報，但**側睡（側臉）是主要誤報來源**，床位模式的 0.8 臉門擋掉側臉反而比 v3 誤報多。`IMG_8114` 還缺說明。
2. **暗光**：賣場拍不了，改在家裡或辦公室補，或留到 Stage II。
3. **口鼻看得到的樣本偏少、側睡尤其少**（照片 49 隻、側睡只有 9 隻；影片誤報樣本也是同一組娃娃）：誤報率還不穩，尤其側睡——`IMG_8184` 已證實側臉是誤報主因。補拍時多拍仰睡、側睡、「趴睡但側臉口鼻看得到」。
4. （可選）閉眼的娃娃：只露眼睛時 YuNet 給 0.77–0.87，閉眼會不會降到門檻以下不知道。

## 10. 怎麼重跑

```bash
uv run python eval_doll.py --det-th 0.15               # v3＋建議門檻
uv run python eval_doll.py --face v4 --det-th 0.15     # v4（口鼻檢查，實驗版）
uv run python eval_doll.py --det-th 0.15 --dim 0.3     # 模擬關燈
uv run python eval_doll.py --det-th 0.15 --gray        # 模擬 IR 夜視（灰階）；加 --dim 0.3＝補光不夠的 IR
uv run python eval_doll.py --det-th 0.15 --max-side 1280  # 模擬 1080p 攝影機
uv run python eval_syrip.py --face v4 --models rtmo    # v4 在 SyRIP 的誤報（再跑 score_relabel.py）
```

改了 `infant_face_v3.py` 或 `infant_face_v4.py` 之後兩邊都要重跑：SyRIP（`eval_syrip.py` ＋ `score_relabel.py`，測真實嬰兒的誤報）和 `eval_doll.py`（娃娃，測危險情境召回）。兩邊都是每隻嬰兒／娃娃各算一次，數字可以直接對照。

**照片授權**：娃娃照片是自己拍的，可以放進簡報和影片（背景有其他客人入鏡的要裁掉或換一張）。`outputs/doll_eval/`、`outputs/syrip_eval/` 和 `dataset/` 不進 GitHub；SyRIP 的圖只能內部看。
