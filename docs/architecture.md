## 一句話

月子中心嬰兒室的每床鏡頭，交給一台邊緣裝置（ASUS UGen300／Hailo-10H）判讀：寶寶臉朝下、口鼻被被子或包巾蓋住，
連續 3 秒看不到口鼻，就先安靜通知護理師——**讓護理師比家長先知道**。AI 判讀在本地、不另存影像。
定位是**輔助護理師觀察，不是醫療器材**；不宣稱預防 SIDS。

## 場景與鏡頭

- 很多月子中心的嬰兒室本來就有**每床一支、從正上方拍**的直播鏡頭（給家長看），新生兒仰躺、臉朝上，正好看得到口鼻。
  一支鏡頭只拍一張床 → **整個畫面就是一個床位**。
- 我們的裝置讀這些既有的鏡頭（實際怎麼接到串流，要跟直播廠商談，是 Stage II 的事），判讀結果送到護理站。
  不新增鏡頭、不另存影像；家長端的直播本來就存在，我們不宣稱「影像不出場域」。
- 2026/10/8 以前的題目是托嬰中心午睡室（一台裝置看整間的多名嬰兒）。托嬰中心的監視器裝在高處、看不到臉，孩子也多半 7–8 個月大，
  所以轉向；程式沿用，因為每床鏡頭就是原本的「床位模式」。

## 判斷流程（每一幀）

1. **RTMO（Apache-2.0）一次找出畫面裡所有人的框和 17 個關鍵點**。
2. **雜訊過濾**：可見身體關鍵點 < 3 個的框當雜訊丟掉（擋大人的手）；兩個框的關鍵點幾乎重疊就當同一人。
3. **每個人的頭部區域依身體方向（髖中點 → 肩中點）轉正、放大，再用 YuNet 找臉**——躺著的臉常是橫的或倒的，轉正才找得到。
4. **床位模式**（`pipeline/crib_detect.py`）：除了透過人找臉，也**直接在床位範圍依床頭方向轉正後找臉**——身體被被子蓋住時，RTMO 常找不到人（娃娃照片只找到兩成），
   臉露在外面還是找得到。臉依位置歸給床位、不透過人框。床位裡找不到臉＝看不到口鼻。
5. **每張床一個警示狀態機**（`pipeline/crib_state.py`）：連續 3 秒看不到口鼻 → 警示；連續 2 秒看得到 → 解除；看得到不到 1 秒不算數（防閃爍）。

**關鍵設計：用人臉偵測器判「臉看不看得到」，不用姿態模型的關鍵點信心度。** 關鍵點信心度的訓練目標是「這個點有沒有被標註」，
不是「看不看得到」——臉埋床單的嬰兒，鼻子、眼睛仍會得到高信心度。分工＝姿態模型負責「人在哪、頭朝哪」，人臉偵測器負責「臉看不看得到」。

## 床位情境：照護中、空床（原型；規則在 `pipeline/crib_state.py`，評估在 `evaluation/crib_context.py`）

每床鏡頭的床位模式有個副作用：寶寶被抱去餵奶、拍嗝，**空床找不到臉，一定響**。不讓護理師每次抱走都手動標記，改成：

1. **大人在床邊 → 照護中**：床位邊緣一圈有明顯動作（大人一定從畫面邊緣伸手進來；先扣掉鏡頭晃動）就暫停計時。
   **已經在響的警示不會因為有人在動而解除**——動作也可能是寶寶在掙扎。
2. **大人離開後，臉不見、而且畫面跟這張床的空床參考畫面相符 → 空床（灰燈）**。不能只看「抓不到嬰兒」：
   空床上 RTMO 會在皺床單上找到人，被蓋住的寶寶又常常抓不到人，兩邊都會錯。
3. **沒有大人來過，就不可能變空床**（寶寶不會自己離開）。
4. 不確定就走一般 3 秒計時——寧可多叫一次。

兩個特徵都在縮成 160 像素的小圖上算，比找臉便宜得多。空床參考是安裝時拍一張（換床單、燈光變了要重拍；比不上就走回一般警示）。

## 第二道檢查：VLM（Stage II 放上 Hailo-10H；筆電上的實驗見 `experiments/vlm_spike.py`）

偵測器每一幀都看、很快，但會被「像臉的東西」騙：頭轉開時，YuNet 會把**耳朵**當成臉。小型視覺語言模型
（Qwen2-VL-2B-Instruct，Apache-2.0；Hailo 官方 GenAI Model Zoo 有為 10H 編好的版本）比較慢、答案也不穩，但它直接回答我們在意的問題：
「看得到寶寶的鼻子和嘴巴嗎？」兩者錯法不同，所以**不對稱地合併**：

- 偵測器判看不到 → 紅燈；VLM 只加註、排序（「先看這床」）。
- 偵測器判看得到、VLM 說看不到 → 黃燈「請看一眼」。
- **VLM 只能多叫人看，不能取消警示**：它的 Yes／No 在肉眼看不出差別的影像變化下有 20–35% 會翻轉；門檻放寬到 0.35，
  會把 82 幀真危險中的 13 幀說成看得到——正是「只露眼睛」那種。
- VLM 要看**床頭的特寫**（床位檔的 `head_x0..head_y1`，安裝時設定）：整張每床畫面縮小後臉只剩約 20 像素，VLM 會亂猜。

筆電（RTX 3050 4GB、語言模型 4-bit）每題 0.2–0.3 秒。在沒看過的兩支每床影片上，安全／危險頭部畫面 AUC 0.98；
偵測器漏掉的 13 幀，門檻 0.4 時全部補到，38 幀安全畫面多出 9 次提醒（多半是側臉）。趴睡判不出來（AUC 0.39–0.64）。
整支影片每秒問一次、**連續 2 次**低於 0.4 才亮黃燈時：偵測器漏掉的危險有 85% 的秒數亮黃燈（46/54），安全片段只有 6% 的秒數多出提醒（11/178）。

**晶片上（2026/11/06，`hailo/vlm_hef.py`）**：Hailo 官方編好的 HEF 跑得起來，每題 1.03 秒，但現在的做法**還不能用**：
- 輸入固定 336×336、API 只回文字不給機率（只能 greedy 答 Yes／No，大約等於門檻 0.5）。
- 同樣兩支影片，看床頭範圍時，晶片版的口鼻題 273 次只答過 1 次 Yes，等於每一幀安全畫面都要人看一眼。同一個筆電模型改成 336 輸入就已經分不太開，量化又讓它更偏向 No。
- 改看 RTMO 的頭部特寫（跟 YuNet 看的那張一樣）：筆電 336 回到原本 448 的水準；晶片上正臉好了，但**側臉全部說看不到**，偵測器漏掉的危險 13/13 都補到，安全畫面卻有 26/38 要人看一眼（筆電版 9/38）。
- 每問一題主流程停約 1 秒（pyHailoRT 跑 VLM 時不放開 GIL，Windows＋USB 又不能把 VLM 放到另一個程序），所以只能有疑慮的床才問。
- 下一步：換一個把側臉也算「看得到」的問法（在別的影片上選）、換 Qwen3-VL-2B，或改做訓練過的口鼻分類器（11/06 先試這個，見下一節）。細節見 `hailo/結果.md`「VLM 複判也放上晶片」。

### 口鼻分類器（實驗，2026/11/06；`experiments/airway_crops.py`、`experiments/airway_train.py`）

VLM 在晶片上還不能用，改試一個只回答這一題的小模型：吃主流程本來就算好的頭部特寫（跟 YuNet 看的是同一張：
以 RTMO 的頭為中心、依身體方向轉正），輸出「口鼻看得到」的機率。它可以用我們自己的娃娃資料訓練，也夠小，可以每幀跑。

- 模型：ResNet18（約 1,100 萬個參數；VLM 是 20 億），從 torchvision 的 ImageNet 預訓練權重開始訓練，輸入 160×160。
  門檻固定 0.5，沒有在評估資料上調。只用 ReLU 這類標準層，之後編 HEF 應該比 RTMO 順（RTMO 量化時 SiLU 吃過虧）。
  筆電上每張頭部特寫 8.6 毫秒（i7-11800H，8 執行緒），GPU（RTX 3050）2.4 毫秒；晶片上還沒量。
- 資料：只用自己拍的娃娃，依影片和拍攝批次分兩半（跟 HEF 校正同一套，`hailo/prep_calib.py` 的 `SPLITS`）。
  訓練用：11/06 試做版用影片 IMG_8115、IMG_8150、IMG_8432，照片第 2、3 批，共 345 張頭部特寫；
  11/09 加上台南那批（一隻 60 公分的照護娃娃：影片 IMG_8735、8739、8740、8741、8742、8744，照片第 4 批），共 1,208 張。
  評估用：影片 IMG_8116、IMG_8184、IMG_8429，照片第 1 批，共 1,086 張；每一版的最後模型只在這裡評估一次。
  影片取沒有手入鏡的片段，每秒 2 幀；趴睡但口鼻看得到算看得到。RTMO 找不到人的幀沒有頭部特寫，照舊交給偵測器。

評估那一半的結果（試做版 → 加台南那批）：

| | 口鼻看得到、判對 | 看不到、判對 |
| --- | --- | --- |
| IMG_8116（危險情境，兩隻娃娃） | 44/44 → 44/44 | 72/72 → 72/72 |
| IMG_8429（每床鏡頭） | 250/282 → 272/282 | 62/66 → 59/66 |
| 照片第 1 批 | 25/37 → 25/37 | 55/56 → 55/56 |
| IMG_8184（6 分鐘正常睡姿，沒有危險） | 282/529 → 283/529 | — |
| 合計 | 601/892（67%）→ 624/892（70%） | 189/194（97%）→ 186/194（96%） |

AUC 0.965 → 0.951。

- 試做版的兩類分得開（AUC 0.965），錯幾乎都在「看得到」那一類，而且大多是同一種：**側躺、側臉，口鼻其實看得到**。
  IMG_8184 的側躺側臉 246 幀全部判成看不到，機率中位數 0.02；同一支影片的仰躺 277 幀只錯 1 幀。
  其他三組標註寫「側」的看得到畫面判對 119/152。
- 原因在訓練資料：可訓練那一半裡「側躺、側臉、口鼻看得到」的畫面很少，看不到那一類卻有很多側頭（例如頭轉開、外套邊緣蓋住口鼻），
  模型就學成「側臉＝看不到」。
- **11/09 加台南那批，主要的錯還在**：台南這批補了側睡（左右各約 50 秒）、只蓋嘴、包巾蓋口鼻的畫面。
  - 試做版沒看過這隻娃娃時，它的側躺朝右 100 幀全錯（朝左 98/98，因為那段臉比較朝向鏡頭）；
    加進訓練後，留一組交叉驗證拿掉 IMG_8744 時，側躺左右 309/312。這隻娃娃的側臉學會了。
  - 但評估那一半幾乎沒變：IMG_8184 的側躺側臉 246 幀還是全錯（機率中位數 0.02 → 0.07）。
    這兩隻娃娃在訓練那一半的 IMG_8150 也有（同一天、同一張床），但那支裡「看得到」的片段全是仰躺正臉，
    側頭只出現在被蓋住的時候；其中一隻側躺、臉朝中間、口鼻清楚，機率只有 0.002。台南娃娃的側臉沒有轉移到這兩隻身上。
  - IMG_8429「包巾只蓋到上半身、側臉口鼻看得到」10 幀也全錯，機率接近 0：同一次拍的 IMG_8432（在訓練那一半）
    用同一件灰色外套蓋口鼻，模型學成「外套在臉旁邊＝看不到」。這就是拍攝說明要「成對拍」的原因。
  - 進步的是 IMG_8429「趴睡蓋被、臉側向」12 → 34/34；退步的是「趴睡、頭在畫面邊緣看不到口鼻」3 → 0/7。
  - 結論：**每一隻娃娃都要拍側臉**，別隻娃娃的側臉學不過來；擋口鼻的東西也要出現在口鼻露出的畫面裡（成對拍）。
    同一隻娃娃多拍，幫助有限。
- 當第二道檢查（評估那一半的影片幀，只算偵測器判「看得到」的；試做版 → 加台南那批）：

| | 偵測器漏掉的危險補到 | 安全畫面多出的提醒 |
| --- | --- | --- |
| IMG_8116 | 16/16 → 16/16 | 0/44 → 0/44 |
| IMG_8429（每床鏡頭） | 48/51 → 45/51 | 10/228 → 10/228 |
| IMG_8184 | — | 174/456 → 173/456 |
| 合計 | 64/67 → 61/67 | 184/728 → 183/728 |

- 偵測器判「看不到」的誤報，第二道檢查管不到。例如台南 IMG_8744 的側躺朝右，YuNet 連續 5 秒找不到側臉就響了。

- 下一步：
  - 下一批訓練資料要**多幾隻娃娃，每一隻都拍側臉**，照 `docs/資料收集說明.md` 拍：B2（側睡、口鼻看得到）、跟 A5 成對拍的 B3，
    擋口鼻的東西（外套、包巾、被子）也要在口鼻露出的畫面裡出現。整批分給訓練或評估，不切成兩半；門檻照舊不調。
  - 側臉在評估那一半過關以前，先不接進主流程。過關後：編成 HEF（校正圖用可訓練那一半的頭部特寫），
    接進主流程當 v6，三套評估重跑（SyRIP 只量誤報、不拿來訓練）。
  - 授權還沒決定：ImageNet 預訓練權重沒有另外標授權，torchvision 提醒預訓練權重可能受訓練資料的條款限制（ImageNet 只允許非商用）。
    作品要放這個模型的話，要先確認可以，或改用授權清楚的預訓練權重。

## 給護理師看的燈號（規劃）

| 燈號 | 意思 |
|---|---|
| 綠 | 口鼻看得到（側臉也是綠，只標「側睡」，不推播——避免側睡造成提醒疲勞） |
| 紅 | 連續 3 秒看不到口鼻，推播 |
| 黃 | 偵測器說看得到、第二道檢查（VLM 或口鼻分類器）說看不到：請看一眼 |
| 藍 | 照護中（大人在床邊），暫停計時 |
| 灰 | 空床 |

## 版本演進

- **v1（`experiments/infant_prone_spike.py`）**：關鍵點信心度規則 → 臉埋床單會漏報，淘汰，留作對照。
- **v2（`experiments/infant_face_spike.py`）**：姿態模型定位嬰兒＋YuNet 找臉。
- **v3（`pipeline/infant_face_v3.py`）＝主力／真實嬰兒基準**：頭部轉正再找臉＋合併重複框。SyRIP 700 張真實嬰兒（人工重標）：
  偵測率 **97.7%**、口鼻看得到時誤報 **6.1%**、口鼻看不到時 **98.6%** 會警示。不依賴 ultralytics（AGPL）。
- **v4（`pipeline/infant_face_v4.py`，實驗）＝v3＋口鼻膚色檢查**：擋「只露眼睛」的假臉。真實嬰兒誤報 10.9%，還沒採用。
- **v5（`pipeline/infant_face_v5.py`，實驗）＝臉分三級**：只有乾淨的側臉才把 alert 降成 warn。娃娃影片誤報最低，但真實嬰兒召回與誤報仍輸 v3。
- **2026/10/9**：警示改成連續 **3 秒**（娃娃影片結果跟 2 秒相同）；CPU 多路負載測試；VLM 第二道檢查的實驗。
- **2026/10/10**：補拍**每床鏡頭版**娃娃影片（一支鏡頭一隻娃娃）——找到「耳朵當成臉」的漏抓，也發現空床一定響 → 床位情境原型。

| v3＋床位（基準） | **31/41（76%）／7/40** | 32/41（78%）／8/40 |

## 模型選擇

- **姿態：RTMO-m（Apache-2.0）**——偵測率最高、一次處理全畫面。備案 RTMPose-m＋YOLOX-m。YOLOv8 出局（AGPL，跟得獎作品要無條件商用＋再授權不相容）。
  **最終以 Hailo-10H 能不能編譯為準**（RTMO 的 ONNX 把解碼包在裡面、輸出人數動態，可能較難轉）。
  11/06 現況：RTMO 切掉解碼、做量化感知訓練後編成 HEF（D1，全部 8 位元），YuNet 也編好；兩個都在 UGen300 上
  接上主流程跑完三套評估。RTMO 上晶片跟原版一樣；YuNet 上晶片差一點、單床反而變慢（[`hailo/結果.md`](../hailo/結果.md)）。
- **人臉：YuNet**（MIT）。
- **VLM：Qwen2-VL-2B-Instruct**（Apache-2.0），Hailo 有 10H 版本。11/06 在 UGen300 上跑起來，但準確度還不能用（上面「第二道檢查」）。
- 不用 MediaPipe Pose（靠臉找人、假設頭看得到，又為單人設計）。

## 運算量（Harry 的筆電，`evaluation/bench_multistream.py`）

UGen300 上（2026/11/06，720p，每床一條執行緒、共用晶片上的模型；細節在 `hailo/結果.md`「主流程的速度」）：

- **RTMO 在晶片、YuNet 在 CPU**：單床每幀 89 ms，合計每秒約 30 幀 → 每床 1 FPS 約 30 床，但 CPU 用到 99%。
- **兩個都在晶片**：單床每幀 153 ms，合計每秒約 15 幀，CPU 只用 35%。YuNet 每幀要呼叫 4–5 次、都是小圖，
  每次含 USB 和主機轉換約 14 ms（晶片本身 2.5 ms），所以放上晶片反而慢；好處是 CPU 留給解串流。

只用 CPU（Intel i7-11800H，每床一個程序、各 1 條執行緒）：

- 完整流程（RTMO＋找臉＋床位）720p 每幀約 190 ms，**其中 7–8 成是 RTMO**；8 個程序合計每秒約 8 幀 → **每床 1 FPS 約 8 床**。
  一間嬰兒室暫抓 25 床（粗估的上限，還沒有正式統計），差約 3 倍——正好是要搬上 UGen300 的部分。
- 只在床位範圍找臉（不跑 RTMO）每幀約 7 ms，便宜 30 倍，但準確率還沒在每床畫面上好好評估。
- 解碼：串流不能跳幀解，25 路原生幀率會吃掉主機大半 CPU → 用鏡頭的子碼流或主機硬體解碼。這是主機的瓶頸，不是 UGen300 的。

## 硬體

UGen300 USB Accelerator（Hailo-10H，40 TOPS INT4，8 GB）。8 GB 記憶體讓 2B 的 VLM 能跟偵測模型放在同一顆晶片上——
這是我們選 10H、而不是任何一顆 NPU 都行的原因（11/06 實測：Qwen2-VL-2B 和 RTMO 同時載入、一起跑沒問題；準確度是另一回事，見上面）。選 USB：插筆電就能開發；每床 1 FPS 的小圖，USB 頻寬夠。

## 已知限制（細節見測試結果文件）

- **還沒有真實新生兒、真實嬰兒室的資料**：所有數字都是替代條件（居家清醒嬰兒照片、娃娃、模擬）。真實場域要等 IRB（Stage II）。
- **頭轉開時把耳朵當成臉**（10/10 補拍）：漏掉危險，比誤報嚴重 → VLM 第二道檢查、Stage II 訓練頭部特寫的小分類器。
- **只蓋住嘴、眼睛露出**：臉照樣找得到 → v4 口鼻檢查部分有效。
- **側臉**是誤報主要來源（v5 處理中）。
- **趴睡但臉側向、口鼻看得到**：口鼻規則不會響；零樣本 VLM 也判不出趴睡。
- **空床判定**只在兩支影片上試過，空床參考要跟床的平常樣子一致。
- **暗光／IR**（程式模擬）：灰階讓真實嬰兒誤報 6.1% → 18.3%，口鼻看不到時仍 98.6% 會警示；口鼻膚色檢查沒有顏色就失效。網路上看到的嬰兒室都有開燈，夜間實況待確認。
- 定位誠實底線：只宣稱「輔助護理師察覺口鼻被遮住」，**不宣稱預防 SIDS**（真正的 SIDS 沒有可觀察的外因）。
