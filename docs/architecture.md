## 一句話

一顆邊緣 AI 晶片同時監測整間托嬰中心午睡室的多名嬰兒，即時標記出現**趴睡、口鼻遮蔽或異常姿勢**的孩子；影像全程不出教室（隱私是硬約束也是賣點）。定位是**輔助托育人員的 co-pilot，不是醫療器材**。

## 判斷流程（pipeline）

每一幀：

1. **RTMO（Apache-2.0）一次找出畫面裡所有人的框和 17 個關鍵點**——一次處理全畫面、成本不隨人數增加，正好對上「同框多嬰兒」。
2. **雜訊過濾**：可見身體關鍵點 < 3 個的框當雜訊丟掉（擋大人的手）；合併重複框（兩個人的關鍵點幾乎重疊就當同一人，留最貼合的）。
3. **每個嬰兒的頭部區域依身體方向（髖中點 → 肩中點）轉正、放大**，再用 **YuNet 找臉**——躺著的臉常是橫的或倒的，轉正才找得到。
4. **判斷每個嬰兒口鼻看不看得到**（見下「三級輸出」）；每個嬰兒各自一個狀態機。

**關鍵設計：用人臉偵測器判「臉看不看得到」，不用姿態模型的關鍵點信心度。** 關鍵點信心度的訓練目標是「這個點有沒有被標註」，不是「看不看得到」——臉埋床單的嬰兒鼻子/眼睛仍會得到高信心度。分工＝姿態模型負責「有幾個嬰兒、頭在哪」，人臉偵測器負責「臉看不看得到」。

## 床位模式（影片／實機）

安裝時在畫面上框出每個床位＋頭朝向。除了透過人找臉，也**直接在床位範圍依方向轉正後找臉**——身體被被子蓋住、RTMO 找不到人時，臉露出來還是找得到。三個實作細節：① 直接在床位範圍找臉（不然「被子蓋到脖子、臉露在外」會誤報）；② 臉依位置歸給床位、不透過人框（兩隻並排被框成一個人時才不會互相拿走臉）；③ 連續 N 秒看不到才警示、看得到要持續才算數（防閃爍）。

之後要加：追蹤每個床位的嬰兒（一開始看得到、之後消失＝被蓋住 → 警示）、區分「抱走 vs 蓋住」（消失前有大人進床位＝抱走）。

## 三級輸出（v5）

- **ok**：正面清楚的臉。
- **warn（側睡）**：側臉但口鼻區合理——側睡口鼻其實看得到，但角度差、也可能滾成趴睡。判斷上側躺／非正面全臉一律 warn（有臨床依據：AAP「back to sleep」，側睡本就不被推薦）。
- **alert**：沒臉／假臉（後腦勺、卡通臉、口鼻被蓋）。

**給老師看的方式（2026/10，依托育現場訪談）**：現場約 8 成寶寶習慣側睡，側臉就提醒會變成老師的負擔，所以 **warn 不推播**——情報版維持綠色、只標「側睡」；口鼻看不到才開始計時（黃），連續達到警示條件才變紅並推播給老師。趴睡要不要另外提醒，等實地參訪、問過托育人員再定；暫定照口鼻規則走（趴睡但看得到側臉＝正常，臉朝下＝計時→警示）。

## 版本演進

- **v1（`infant_prone_spike.py`）**：關鍵點信心度規則 → 臉埋床單會漏報，淘汰，留作對照。
- **v2（`infant_face_spike.py`）**：姿態模型定位嬰兒＋YuNet 找臉。
- **v3（`infant_face_v3.py`）＝目前的主力／真實嬰兒基準**：頭部轉正再找臉＋合併重複框。SyRIP 700 張真實嬰兒（人工重標）：偵測率 **97.7%**、口鼻看得到時誤報 **6.1%**、口鼻看不到時 **98.6%** 會警示。不依賴 ultralytics（AGPL），共用函式在 `face_common.py`。
- **v4（`infant_face_v4.py`，實驗）＝v3＋口鼻膚色檢查**：擋「只露眼睛」的假臉（衣領／玩偶／被子蓋住口鼻，YuNet 仍給 0.77–0.87）。2026/9/23 改良（只看鼻子人中、避開嘴巴、臉太小不檢查）後，真實嬰兒誤報 16.6% → **10.9%**、召回維持 98.6%。
- **v5（`infant_face_v5.py`，實驗）＝臉三級（混合架構）**：v4 當 alert 骨幹（保召回）、幾何把可見的臉分 ok/warn、**只有乾淨有把握的側臉才把 alert 降成 warn**。娃娃影片召回 91%、誤報 3/33（床位模式原本 8–9/33）；真實嬰兒誤報 9.3%、召回 81.9%。**因真實嬰兒召回與誤報仍輸 v3，先當實驗版，v3 仍是基準。**

（`--face v3/v4/v5` 切換；床位/影片評估 `eval_video.py` 的 `v3/v3_slot/v4_slot/v5_slot` 模式。）

## 模型選擇

- **姿態：RTMO-m（Apache-2.0）**——偵測率最高、一次處理全畫面、成本不隨人數增加。備案 RTMPose-m＋YOLOX-m。YOLOv8 出局（AGPL，跟得獎作品要無條件商用＋再授權不相容）。**最終以 Hailo-10H 能不能編譯為準**（RTMO 的 ONNX 把解碼包在裡面、輸出人數動態，可能較難轉；士丞在測 HEF）。
- **人臉：YuNet**（授權寬鬆）。
- 不用 MediaPipe Pose（靠臉找人、論文明寫假設頭看得到，又為單人設計）。

## 硬體

UGen300 USB Accelerator（Hailo-10H，40 TOPS INT4，8GB）。選 USB 非 M.2：插筆電就能開發（開發確定性最高），本場景單串流多目標用不到 M.2 的頻寬優勢。

## 已知限制（細節見測試結果文件、待辦見 status.md）

- **側臉**是誤報主要來源（v5 warn 處理中）；真實嬰兒誤報 v3 最低 6.1%、v4/v5 稍高。
- **身體被被子蓋住 → RTMO 找不到人**，靠床位模式直接找臉補。
- **暗光／IR 夜視（程式模擬，2026/9/29）**：灰階讓真實嬰兒（SyRIP）誤報 6.1% → 18.3%，口鼻看不到時仍 98.6% 會警示——多出來的是誤報不是漏報。原因是彩色時就在門檻邊緣的小臉、側臉，在灰階下分數會整張掉光；口鼻膚色檢查（v4/v5）沒有顏色就失效。→ 安裝時優先彩色畫面（低照度彩色攝影機或小夜燈；法規也要求托嬰中心睡眠區的監視畫面為彩色），夜視模式要自己的門檻和不靠顏色的口鼻遮蔽判斷，並用實拍驗證（`docs/娃娃測試結果.md` §8、`docs/影片測試結果.md` §3e–3f）。實際午睡時畫面是彩色還是黑白，要到托嬰中心確認。
- **天花板遠距（小臉）、真實嬰兒影片（時序）、實拍 IR** 都還沒測——見 status.md 待辦。小臉＋IR 是最壞的組合。
- 定位誠實底線：只宣稱「降低可觀察的姿勢性風險、輔助照顧者察覺」，**不宣稱預防 SIDS**（真正的 SIDS 無可觀察外因，影像偵測不到）。
