**9/22，加入 6 分鐘正常睡姿影片（IMG_8184），戳破了「0 誤報」的假象**：那個 0 是因為 8116／8150 的安全片段大多是**正面仰睡**。IMG_8184 一半以上是**側睡（側臉）**，這時 YuNet 側臉分數低（約 0.7），加上身體常被被子蓋住讓 RTMO 抓不到人——床位模式直接找臉又被 0.8 門檻擋掉 → **床位模式反而比 v3 多誤報**（安全段 v3 2/13、v3＋床位 5/13）。正面仰睡仍是 0 誤報；**誤報全部集中在「側睡」和「身體被蓋住、臉露在外」**。這是側臉偵測的缺口，不是娃娃不夠好（見 §3c）。

**9/22–23，v5＝把臉改成三級（正臉 ok／側臉 warn／沒臉或假臉 alert），混合架構（見 §3d）**：v4 當 alert 骨幹保召回，幾何只把「本來看得到的臉」分 ok/warn、只有乾淨側臉才把 alert 降成 warn。**影片上成功**：危險召回 91%、安全誤報 8–9/33 → **3/33**、IMG_8184 側睡誤報 5–6/13 → 2/13（9/29 用現行程式重跑是 1/13，IMG_8115 則是 2/3，合計仍 3/33）、側臉 87% 判成 warn。**並改良了 v4 口鼻膚色檢查（2026/9/23）**：只看鼻子人中、臉太小不檢查 → 真實嬰兒（SyRIP）誤報 v4 16.6% → **10.9%**、v5 14.7% → **9.3%**（召回 v4 維持 98.6%、v5 81.9%）。**但 v3 仍是真實嬰兒誤報最低（6.1%）→ v5 先當實驗版、v3 仍是基準**，差距已拉近。要讓 v5 上線還缺：口鼻膚色再收、拍真實嬰兒影片。

## 1. 怎麼測

- **每秒取 5 幀**，每幀跑 v3（RTMO 找人＋YuNet 找臉，找人門檻 0.15）。
- **床位**：像安裝時一樣，在畫面上框出床位，並記下頭朝哪邊（IMG_8116、8150、8184 頭朝畫面下方；IMG_8115 一個床位涵蓋整床、頭朝上）。
- **標註**：Harry 的時間軸 → 我逐段看畫面核對 → **只取手不在畫面裡的乾淨片段**，手在擺娃娃的過渡期不計分。四支共 72 段：危險 34 段、安全 38 段（其中 5 段太短，只算每幀判定、不算誤報，所以安全片段計分 33 段）。最初兩支是 52 段：危險 31、安全 21（4 段太短）。
  - 跟 Harry 說明的差異：`IMG_8116` 的「側躺」「趴睡頭往側邊」從這個角度看都是後腦勺或側臉朝上、看不到口鼻，依規則算警示（拍攝意圖記「注意」）；`IMG_8150` 0:28–0:35 左邊那隻，放大後嘴唇在被子邊緣上方看得到，維持正常。
- **警示規則**（每個床位一個狀態機）：連續 2 秒看不到口鼻才警示、連續 2 秒看得到才解除；看得到要持續 1 秒以上才把「看不到」的計時歸零（防閃爍，見 §5 第 3 點）。**2026/10/9 起預設改成連續 3 秒才警示**（解除仍是 2 秒）；用現有每幀結果重算，四支影片的合計跟 2 秒完全相同（v3＋床位 29/34、誤報 8/33；v5＋床位 31/34、3/33），每路降到 1–2 FPS 也幾乎不變。本文件其餘數字是 2 秒時跑的。
- **計分**：
  - 危險片段：**到片段結束那一刻還在警示才算抓到**。手擺娃娃時會擋住畫面，警示可能在過渡期就響了，只看開頭有沒有響會高估。
  - 安全片段：扣掉開頭 2 秒（前一段的警示還在解除），之後有響就算誤報。

這是一直要的「5–10 分鐘正常睡姿影片，專門量誤報」。兩隻娃娃並排、頭朝畫面下方（rot 180），6 分鐘裡幾乎全是口鼻看得到的姿勢：正面仰睡、側睡（側臉鼻子嘴唇看得到）、身體被棉被或玩偶蓋住但臉露在外。標了 13 段安全片段、0 段危險（設計如此）。

|---|---|---|---|---|
| 全部 13 段 | **2/13** | **5/13** | 6/13 | **1/13** |

| 其中側睡／身體被蓋住 | 2 | 5 | 6 | 1 |

**誤報全部集中在「側睡（側臉）」和「身體被被子／玩偶蓋住、臉露在外」**，機制（看 `outputs/video_eval/IMG_8184_frames.csv`）：

1. **側臉分數低於床位門檻**：娃娃側睡時 YuNet 給的臉分數約 0.7；透過人找臉的門檻較低（右娃 0.70 接受得到），但床位模式**直接找臉用的是 0.8**（當初調高是為了擋抱枕卡通臉，`eval_video.SLOT_FACE_TH`），側臉 0.7 被擋掉 → 判「看不到口鼻」。0:44 正面仰睡時床位找臉是 0.91，就找得到。
2. **身體被蓋住 → RTMO 抓不到人（n=0）**：棉被段（3:12–3:50）、玩偶段（4:15–4:53）RTMO 完全不輸出人，只能靠床位直接找臉；偏偏娃娃是側臉 → 被 0.8 門檻擋掉 → 床位模式誤報。v3 因為「沒人就不警示」反而是灰色不誤報（但也等於沒在監測）。
3. **左娃側躺透過人也常找不到臉**（2:20–2:58，`face` 大多是空的、偶爾 0.81）→ 連 v3 都誤報；右娃同時間 0.70 接受得到 → 右娃正常。左右差別只在朝向角度。

**這修正了先前「床位模式 0 誤報」的印象**：8116／8150 的安全段大多是正面仰睡才會 0 誤報。真實午睡室一定有大量側睡，**側臉是誤報的主要來源**，而床位模式目前的 0.8 門檻讓它在側睡上比 v3 更糟。時間軸圖 `outputs/video_eval/IMG_8184_timeline.png` 一眼看得出來：GT 綠色（口鼻看得到）底下，床位那兩列在側睡段和被蓋住段是紅的（誤報）。

>
> **2026/10/2 修訂（通知政策）**：托嬰協會理事長說約八成寶寶側睡，一直提醒會增加老師負擔。warn 仍保留在判斷和標註裡，但介面上顯示**綠色、只標「側睡」、不推播**；口鼻看不到才計時，達到警示才推播（`docs/demo規格.md` §2）。評估數字不受影響。

## 3d. v5：把「臉」改成三級（ok／warn／alert）——混合架構（2026/9/22）

`infant_face_v5.py`。第一版試「降門檻直接當主力」，娃娃上漂亮但**真實嬰兒（SyRIP）召回崩掉**（臉看不到→ALERT 98.6%→46%），所以改成 **混合架構**（Harry 拍板 (b)）：
- **backbone＝v4**（正常門檻找臉＋口鼻膚色）決定 visible／alert → **不動 alert 的召回骨幹**。
- backbone 判 **visible** 的臉：用特徵點幾何 eye_asym 分 **正臉→ok**、**側臉→warn**（只是把可見再分兩級）。
- backbone 判 **alert** 時：另外用低門檻(0.3)找臉，**只有找到「乾淨、有把握的側臉」（分數≥0.5、eye_asym∈[0.8,1.3]、結構合理、口鼻區有膚色）才把 alert 降成 warn**，否則維持 alert。寧可保守。

warn＝側睡／需關注，不算硬警示、不算硬誤報（當時設計成軟提醒；2026/10/2 起介面上顯示綠色＋「側睡」、不推播，見 §3c 的修訂說明）。

|---|---|---|
| v3 | 13/34（38%） | 2/33 |
| v3＋床位 | 29/34（85%） | 8/33 |

## 3e. 灰階／暗光（模擬 IR 夜視，2026/9/29）

## 6. 限制（簡報要誠實講）

- **樣本小**：都是同 2 隻娃娃、同一張床。危險情境影片（8116／8150）的安全片段只有 17 段、都很短（2–6 秒）且大多是仰睡正臉——這就是為什麼那兩支「0 誤報」。**6 分鐘的 IMG_8184 補上了這個缺口**：它有大量側睡，量出來誤報並不是 0（v3 2/13、床位 5/13），主因是側臉（見 §3c）。誤報樣本仍偏少（同一組娃娃），實機要在真實午睡室重量。
- **側臉是目前最大的誤報來源，也是還沒解的技術缺口**：YuNet 是正面臉偵測器，側臉分數約 0.7，床位模式的 0.8 門檻把它擋掉。娃娃只有一種臉、側臉時鼻子嘴唇其實看得到，真實嬰兒側睡更多 → 這個問題在實機只會更嚴重。v5 在娃娃影片上把誤報從 8/33 降到 3/33，但在真實嬰兒和灰階下都還沒站穩（§3d、§3e）。
- **量不到警示延遲**：危險狀態是手擺出來的，擺的過程中手就擋住畫面，警示常在手離開前就響了。真實嬰兒翻身沒有手，延遲大約就是規則設定的 2 秒。
- **鏡頭很近**（約 1 公尺）：臉很大。天花板鏡頭看整間午睡室時臉會小很多，照片測試縮到 1080p 時口鼻檢查已經開始誤擋。
- **v4 還沒通過真實嬰兒的誤報測試**（SyRIP 誤報：v3 6.1%；v4 原本 16.6%，9/23 改良後 10.9%，仍高於 v3），影片上的高召回只代表娃娃。
- **暗光／IR 只有模擬**（§3e）：影片全是開燈彩色拍的，灰階、壓暗是程式做的；翻身影片雖然是灰階夜視畫面，但是 AI 生成的。要用夜視攝影機實拍一段娃娃影片才算數。

## 怎麼重跑

```bash
uv run python eval_video.py                          # 全部影片（每支約 2–3 分鐘）
uv run python eval_video.py IMG_8150                 # 只跑一支
uv run python eval_video.py --reuse --on 3 --off 3   # 不重跑偵測，只換警示規則重算
uv run python eval_video.py --preview v4_slot        # 標註影片的床位框改依 v4＋床位
uv run python eval_video.py --gray --dim 0.3         # 模擬補光不夠的 IR 夜視（輸出到 outputs/video_eval_gray_dim0.3/）
uv run python eval_video.py 嬰兒翻身                  # 非娃娃的翻身影片（見 §3f），要指定名稱才跑
```

新影片要計分：在 `doll_video_slots.csv` 加床位（框＋頭朝哪邊）、在 `doll_video_labels.csv` 加每段狀態（只列手不在畫面裡的乾淨片段）。非娃娃影片登記在 `eval_video.NOT_DOLL`——不給名稱時不會跑、也不混進娃娃影片的合計。不能公開的素材，標註放在不進 repo 的 `local_video_slots.csv`／`local_video_labels.csv`（格式相同，見 `video_labels.py`）。
