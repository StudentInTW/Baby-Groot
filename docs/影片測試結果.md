# 娃娃影片測試結果（2026/9/21）

資料：`dataset/doll_video/` 的 `IMG_8116`（2:12）和 `IMG_8150`（2:50），手機固定在床正上方約 1 公尺、錄影時用手擺娃娃。Harry 的說明檔是同名的 `.txt`。`IMG_8114`、`IMG_8115` 還沒有說明，沒有計分。
程式：`eval_video.py`。標註：`doll_video_labels.csv`（52 段）、`doll_video_slots.csv`（床位）。輸出：`outputs/video_eval/`。

## 一句話

**床位模式在影片上驗證成功：危險片段抓到 32% → 84%，安全片段 0 誤報。** 加上口鼻檢查（v4）是 97%，唯一漏掉的是「趴睡、頭往側邊」。但 v4 在真實嬰兒照上誤報太多（`docs/娃娃測試結果.md` §5），影片的 97% 不能直接當產品數字。

## 1. 怎麼測

- **每秒取 5 幀**，每幀跑 v3（RTMO 找人＋YuNet 找臉，找人門檻 0.15）。
- **床位**：像安裝時一樣，在畫面上框出兩個床位，並記下頭朝哪邊（這兩支都是頭朝畫面下方）。
- **標註**：Harry 的時間軸 → 我逐段看畫面核對 → **只取手不在畫面裡的乾淨片段**，手在擺娃娃的過渡期不計分。共 52 段：危險 31 段、安全 21 段（其中 4 段太短，只算每幀判定、不算誤報）。
  - 跟 Harry 說明的差異：`IMG_8116` 的「側躺」「趴睡頭往側邊」從這個角度看都是後腦勺或側臉朝上、看不到口鼻，依規則算警示（拍攝意圖記「注意」）；`IMG_8150` 0:28–0:35 左邊那隻，放大後嘴唇在被子邊緣上方看得到，維持正常。
- **警示規則**（每個床位一個狀態機）：連續 2 秒看不到口鼻才警示、連續 2 秒看得到才解除；看得到要持續 1 秒以上才把「看不到」的計時歸零（防閃爍，`context.md` §8 第 5 項）。
- **計分**：
  - 危險片段：**到片段結束那一刻還在警示才算抓到**。手擺娃娃時會擋住畫面，警示可能在過渡期就響了，只看開頭有沒有響會高估。
  - 安全片段：扣掉開頭 2 秒（前一段的警示還在解除），之後有響就算誤報。

## 2. 比較三種判定

| 判定 | 做法 |
|---|---|
| **v3** | 現在的主力程式：床位裡偵測到人、找不到臉 → 警示；**沒偵測到人 → 不警示** |
| **v3＋床位** | 床位模式：① 找到的臉**依位置**歸給床位（不透過人框）；② 另外**直接在床位範圍依床位方向轉正後找臉**，身體蓋在被子下、姿態模型找不到人也找得到；③ 床位裡找不到臉 → 看不到口鼻 |
| **v4＋床位** | 再加口鼻檢查（`infant_face_v4.py`，實驗版） |

## 3. 結果

| | 危險片段抓到 | 危險時間裡在警示的比例 | 安全片段誤報 |
|---|---|---|---|
| v3 | 10/31（32%） | 34% | 0/17 |
| **v3＋床位** | **26/31（84%）** | 87% | **0/17** |
| v4＋床位 | 30/31（97%） | 98% | 0/17 |

| 影片 | 內容 | v3 | v3＋床位 | v4＋床位 |
|---|---|---|---|---|
| `IMG_8116` | 被子蓋臉、側躺、趴睡、趴睡頭往側邊 | 8/15 | 13/15 | 14/15 |
| `IMG_8150` | 衣領、被子、玩偶蓋住口鼻 | 2/16 | 13/16 | 16/16 |

- **換警示參數結果差不多**：連續 1–5 秒才警示，v3＋床位都是 81–84%、v4＋床位 94–97%，全部 0 誤報，不是剛好調對參數。不防閃爍時分別是 81%、94%。
- 時間軸對照圖（`outputs/video_eval/*_timeline.png`）一眼看得出來：**v3 那一列大多是灰色**——姿態模型根本沒偵測到這隻娃娃（身體蓋在被子下或在畫面邊緣），所以不會警示。跟照片測試的結論一樣（`docs/娃娃測試結果.md` §6-A）。

## 4. 床位模式還漏掉的 5 段

| 片段 | 情況 | v4 |
|---|---|---|
| `IMG_8150` 0:02 右、2:04 右 | 衣領蓋住口鼻，只露眼睛 → YuNet 還是找到臉 | 抓到 |
| `IMG_8150` 2:36 左 | 玩偶蓋住口鼻，只露一隻眼 | 抓到 |
| `IMG_8116` 1:52 右、2:06 右 | 趴睡、頭往側邊：鏡頭看到側臉和耳朵，被當成臉，下半臉那塊也確實是皮膚 | 抓到 1 段 |

前三段就是照片測試裡的「只露眼睛的假臉」，口鼻檢查能擋。後兩段是已知的「側臉／後腦勺假臉」，口鼻檢查擋不住；這個姿勢 Harry 標「注意」，之後要靠**趴睡判斷**處理（`context.md` §8 第 5 項：趴睡但口鼻看得到也要橘色提醒）。

## 5. 這次測出來的三個床位模式細節

1. **直接在床位範圍找臉**：`IMG_8116` 0:20 右邊那隻被子蓋到脖子、臉露在外面，但 RTMO 不輸出這個人。只靠「人」找臉的話，床位模式會對它**誤報**（第一版試跑就是這樣）。床位知道頭朝哪邊，轉正後直接找臉就找得到（0.88 分）。
2. **臉依位置歸給床位**：`IMG_8150` 0:22 右邊的「人」同時配到自己被蓋住的臉和左邊露出來的臉，右邊就被判成看得到。改成依臉的位置歸給床位後就不會拿走鄰床的臉。
3. **防閃爍**：口鼻檢查的數值在門檻附近跳動時，偶爾一幀判成看得到，會把「連續 2 秒」的計時歸零。看得到要持續 1 秒以上才算數。

這三點都要做進正式版的床位模式。

## 6. 限制（簡報要誠實講）

- **樣本小**：2 支影片、同 2 隻娃娃、同一張床。安全片段只有 17 段、都很短（2–6 秒），而且大多是仰睡正臉。**誤報率要靠更長的正常睡姿影片才量得準**——建議拍一段 5–10 分鐘，娃娃仰睡或側睡、偶爾有人走過床邊。
- **量不到警示延遲**：危險狀態是手擺出來的，擺的過程中手就擋住畫面，警示常在手離開前就響了。真實嬰兒翻身沒有手，延遲大約就是規則設定的 2 秒。
- **鏡頭很近**（約 1 公尺）：臉很大。天花板鏡頭看整間午睡室時臉會小很多，照片測試縮到 1080p 時口鼻檢查已經開始誤擋。
- **v4 還沒通過真實嬰兒的誤報測試**（SyRIP 6.1% → 16.6%），影片上的 97% 只代表娃娃。

## 7. 產出

- `outputs/video_eval/<影片>_timeline.png`：時間軸對照圖（標註、三種判定的每幀結果、警示中）。娃娃是自己拍的，**可以放進簡報**。
- `outputs/video_eval/<影片>_preview.mp4`：標註影片（每秒 5 幀、寬 540）。床位框紅＝警示中（預設依 v3＋床位），黃框＝找到的臉，橘框＝口鼻檢查判成被蓋住。框和警示都是系統真的跑出來的，**可以當 demo 影片的底稿**。
- `outputs/video_eval/<影片>_frames.csv`：每幀每個床位的判定和臉的分數。

## 怎麼重跑

```bash
uv run python eval_video.py                          # 全部影片（每支約 2–3 分鐘）
uv run python eval_video.py IMG_8150                 # 只跑一支
uv run python eval_video.py --reuse --on 3 --off 3   # 不重跑偵測，只換警示規則重算
uv run python eval_video.py --preview v4_slot        # 標註影片的床位框改依 v4＋床位
```

新影片要計分：在 `doll_video_slots.csv` 加床位（框＋頭朝哪邊）、在 `doll_video_labels.csv` 加每段狀態（只列手不在畫面裡的乾淨片段）。
