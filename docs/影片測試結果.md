資料：`dataset/doll_video/`，手機固定在床正上方約 1 公尺。每支的說明檔是同名 `.txt`。
- **危險情境影片**（測床位模式召回）：`IMG_8116`（2:12，兩隻）、`IMG_8150`（2:50，兩隻）、`IMG_8115`（1:29，**單一娃娃＋貓咪抱枕**，2026/9/22 補說明後計分）。
- **正常睡姿影片**（測誤報，`context.md` §8/§9 一直缺的樣本）：`IMG_8184`（**6:02，兩隻娃娃並排**，幾乎整支都是口鼻看得到的仰睡／側睡／身體被蓋住但臉露在外）。
- `IMG_8114`（0:55）仍沒有說明，未計分。

程式：`eval_video.py`。標註：`doll_video_labels.csv`、`doll_video_slots.csv`（床位）。輸出：`outputs/video_eval/`。

## 一句話

**床位模式在危險情境影片上驗證成功：危險片段抓到 32% → 84%，安全片段 0 誤報（IMG_8116、8150）。** 加上口鼻檢查（v4）是 97%，唯一漏掉的是「趴睡、頭往側邊」。但 v4 在真實嬰兒照上誤報太多（`docs/娃娃測試結果.md` §5），影片的 97% 不能直接當產品數字。

**但 6 分鐘的正常睡姿影片（IMG_8184）戳破了「0 誤報」的假象**：那個 0 是因為 8116／8150 的安全片段大多是**正面仰睡**。IMG_8184 一半以上是**側睡（側臉）**，這時 YuNet 側臉分數低（約 0.7），加上身體常被被子蓋住讓 RTMO 抓不到人——床位模式直接找臉又被 0.8 門檻擋掉 → **床位模式反而比 v3 多誤報**（安全段 v3 2/13、v3＋床位 5/13）。正面仰睡仍是 0 誤報；**誤報全部集中在「側睡」和「身體被蓋住、臉露在外」**。這是側臉偵測的缺口，不是娃娃不夠好（見 §3c）。

**v5＝把臉改成三級（正臉 ok／側臉 warn／沒臉或假臉 alert），混合架構（2026/9/22，見 §3d）**：v4 當 alert 骨幹保召回，幾何只把「本來看得到的臉」分 ok/warn、只有乾淨側臉才把 alert 降成 warn。**影片上很成功**：危險召回 97%（跟 v4 一樣）、安全誤報 8–9/33 → **4/33**、IMG_8184 側睡誤報 5–6/13 → 2/13、側臉 86% 判成 warn。**但真實嬰兒（SyRIP）上還輸 v3**：召回 87.5%（v3 是 98.6%）、誤報 14.7%（v3 是 6.1%，這 14.7% 主要是 v4 口鼻膚色對真實正臉的過度拒絕、跟側臉無關）。**所以 v5 先當實驗版，v3 仍是真實嬰兒基準**；要讓 v5 上線還缺：改良 v4 口鼻膚色、拍真實嬰兒影片。

## 1. 怎麼測

- **每秒取 5 幀**，每幀跑 v3（RTMO 找人＋YuNet 找臉，找人門檻 0.15）。
- **床位**：像安裝時一樣，在畫面上框出兩個床位，並記下頭朝哪邊（這兩支都是頭朝畫面下方）。
- **標註**：Harry 的時間軸 → 我逐段看畫面核對 → **只取手不在畫面裡的乾淨片段**，手在擺娃娃的過渡期不計分。共 52 段：危險 31 段、安全 21 段（其中 4 段太短，只算每幀判定、不算誤報）。
  - 跟 Harry 說明的差異：`IMG_8116` 的「側躺」「趴睡頭往側邊」從這個角度看都是後腦勺或側臉朝上、看不到口鼻，依規則算警示（拍攝意圖記「注意」）；`IMG_8150` 0:28–0:35 左邊那隻，放大後嘴唇在被子邊緣上方看得到，維持正常。
- **警示規則**（每個床位一個狀態機）：連續 2 秒看不到口鼻才警示、連續 2 秒看得到才解除；看得到要持續 1 秒以上才把「看不到」的計時歸零（防閃爍，`context.md` §8 第 5 項）。
- **計分**：
  - 危險片段：**到片段結束那一刻還在警示才算抓到**。手擺娃娃時會擋住畫面，警示可能在過渡期就響了，只看開頭有沒有響會高估。
  - 安全片段：扣掉開頭 2 秒（前一段的警示還在解除），之後有響就算誤報。

## 2. 比較三種判定

| 判定 | 做法 |
|---|---|
| **v3** | 現在的主力程式：床位裡偵測到人、找不到臉 → 警示；**沒偵測到人 → 不警示** |
| **v3＋床位** | 床位模式：① 找到的臉**依位置**歸給床位（不透過人框）；② 另外**直接在床位範圍依床位方向轉正後找臉**，身體蓋在被子下、姿態模型找不到人也找得到；③ 床位裡找不到臉 → 看不到口鼻 |
| **v4＋床位** | 再加口鼻檢查（`infant_face_v4.py`，實驗版） |

- 結論：IMG_8115 的主要價值是**再次證明卡通臉會騙過 v3、只有口鼻檢查擋得住**；它不適合當床位模式的召回樣本。

## 3c. IMG_8184：6 分鐘正常睡姿影片——誤報率的真實樣本

這是 `context.md` §8/§9 一直要的「5–10 分鐘正常睡姿影片，專門量誤報」。兩隻娃娃並排、頭朝畫面下方（rot 180），6 分鐘裡幾乎全是口鼻看得到的姿勢：正面仰睡、側睡（側臉鼻子嘴唇看得到）、身體被棉被或玩偶蓋住但臉露在外。標了 13 段安全片段、0 段危險（設計如此）。

| 安全片段誤報 | v3 | v3＋床位 | v4＋床位 |
|---|---|---|---|
| 全部 13 段 | **2/13** | **5/13** | 6/13 |
| 其中正面仰睡（0:10–0:55、5:52–6:00） | 0 | 0 | 0 |
| 其中側睡／身體被蓋住 | 2 | 5 | 6 |

**誤報全部集中在「側睡（側臉）」和「身體被被子／玩偶蓋住、臉露在外」**，機制（看 `outputs/video_eval/IMG_8184_frames.csv`）：

1. **側臉分數低於床位門檻**：娃娃側睡時 YuNet 給的臉分數約 0.7；透過人找臉的門檻較低（右娃 0.70 接受得到），但床位模式**直接找臉用的是 0.8**（當初調高是為了擋抱枕卡通臉，`eval_video.SLOT_FACE_TH`），側臉 0.7 被擋掉 → 判「看不到口鼻」。0:44 正面仰睡時床位找臉是 0.91，就找得到。
2. **身體被蓋住 → RTMO 抓不到人（n=0）**：棉被段（3:12–3:50）、玩偶段（4:15–4:53）RTMO 完全不輸出人，只能靠床位直接找臉；偏偏娃娃是側臉 → 被 0.8 門檻擋掉 → 床位模式誤報。v3 因為「沒人就不警示」反而是灰色不誤報（但也等於沒在監測）。
3. **左娃側躺透過人也常找不到臉**（2:20–2:58，`face` 大多是空的、偶爾 0.81）→ 連 v3 都誤報；右娃同時間 0.70 接受得到 → 右娃正常。左右差別只在朝向角度。

**這修正了先前「床位模式 0 誤報」的印象**：8116／8150 的安全段大多是正面仰睡才會 0 誤報。真實午睡室一定有大量側睡，**側臉是誤報的主要來源**，而床位模式目前的 0.8 門檻讓它在側睡上比 v3 更糟。時間軸圖 `outputs/video_eval/IMG_8184_timeline.png` 一眼看得出來：GT 綠色（口鼻看得到）底下，床位那兩列在側睡段和被蓋住段是紅的（誤報）。

> **標註政策（Harry 已定，2026/9/22）**：側躺／非正面全臉＝**warn（需關注）**，不改成 ok 也不算 alert；正面全臉才是 ok。這裡把「側臉、鏡頭看得到鼻子嘴唇」的段標成 `ok`（airway 看得到）當作誤報的分母，是為了量「側臉會不會被硬警示」；產品層 v5 把它判成 warn（軟提醒），不算硬誤報（見 §3d）。維持床位找臉門檻 0.8 的路線改由 v5 用「降門檻＋幾何分級」處理，不為數字改政策。

## 3d. v5：把「臉」改成三級（ok／warn／alert）——混合架構（2026/9/22）

`infant_face_v5.py`。第一版試「降門檻直接當主力」，娃娃上漂亮但**真實嬰兒（SyRIP）召回崩掉**（臉看不到→ALERT 98.6%→46%），所以改成 **混合架構**（Harry 拍板 (b)）：
- **backbone＝v4**（正常門檻找臉＋口鼻膚色）決定 visible／alert → **不動 alert 的召回骨幹**。
- backbone 判 **visible** 的臉：用特徵點幾何 eye_asym 分 **正臉→ok**、**側臉→warn**（只是把可見再分兩級）。
- backbone 判 **alert** 時：另外用低門檻(0.3)找臉，**只有找到「乾淨、有把握的側臉」（分數≥0.5、eye_asym∈[0.8,1.3]、結構合理、口鼻區有膚色）才把 alert 降成 warn**，否則維持 alert。寧可保守。

warn＝軟提醒（側睡/需關注，看一眼），不算硬警示、不算硬誤報。

**四支娃娃影片合計**（warn 不算硬警示）：

| | 危險片段抓到 | 安全片段誤報 |
|---|---|---|
| v3 | 13/34（38%） | 2/33 |
| v3＋床位 | 29/34（85%） | 8/33 |
| v4＋床位 | 33/34（97%） | 9/33 |
| **v5＋床位** | **33/34（97%）** | **4/33** |

- **影片上 v5 是第一個同時做到高召回（97%）和低誤報（4/33，床位模式原本 8–9）的版本**；IMG_8184 側睡誤報 5–6/13 → **2/13**。
- **三級分布（每幀）**：正臉 96% ok、側臉 **86% warn**、危險 **94% alert**（比第一版「降門檻當主力」的 89% 更可靠地判危險——保守降級奏效）。

**真實嬰兒（SyRIP）確認——這才是關鍵，v5 還不能取代 v3**：

| | 真實誤報（重標） | 臉看不到→ALERT |
|---|---|---|
| v3 | **6.1%** | **98.6%（71/72）** |
| v4 | 16.6% | 98.6% |
| v5 第一版（降門檻當主力） | 13.0% | 46%（33/72）❌ |
| **v5 混合** | 14.7% | **87.5%（63/72）** |

- 混合版把真實嬰兒召回從 46% 救回 **87.5%**（保守降級只誤降 9 張真實埋臉）——但**仍未回到 v3/v4 的 98.6%**；誤報 14.7% ≈ v4（backbone 是 v4 的口鼻膚色，繼承了它對真實正臉的過度拒絕，跟側臉無關）。
- **結論：v5 影片漂亮、三級概念對，但在真實嬰兒上召回和誤報都還輸 v3 → v5 先當實驗版（`--face v5`／`v5_slot`），v3 仍是真實嬰兒的基準。** 影片沒掉是因為有時序、SyRIP 是單張最吃虧，兩個因素分不開，除非有真實嬰兒影片。

**殘留與下一步**：
- 真實嬰兒誤報 14.7% 的主因是 **v4 口鼻膚色對真實正臉的過度拒絕**（小臉、張嘴哭、戴帽），不是側臉——要做 v4 口鼻檢查的改良（只看鼻子人中、臉太小不檢查，`docs/娃娃測試結果.md` §5），跟 v5 的側臉分級是兩件事。
- 混合版誤降的 9 張真實埋臉：單鏡頭下「頭轉側邊、臉頰露出」跟真側睡幾乎一樣（IMG_8115 趴貓咪抱枕 0:36 就是），只能靠真實嬰兒影片＋時序才分得開。
- IMG_8184 3:12–3:50 R 還誤報：那個側臉分數 0.44 < 降級門檻 0.5，保守維持 alert；降門檻會救它但真實嬰兒召回會再掉——不硬調。

## 5. 這次測出來的三個床位模式細節

1. **直接在床位範圍找臉**：`IMG_8116` 0:20 右邊那隻被子蓋到脖子、臉露在外面，但 RTMO 不輸出這個人。只靠「人」找臉的話，床位模式會對它**誤報**（第一版試跑就是這樣）。床位知道頭朝哪邊，轉正後直接找臉就找得到（0.88 分）。
2. **臉依位置歸給床位**：`IMG_8150` 0:22 右邊的「人」同時配到自己被蓋住的臉和左邊露出來的臉，右邊就被判成看得到。改成依臉的位置歸給床位後就不會拿走鄰床的臉。
3. **防閃爍**：口鼻檢查的數值在門檻附近跳動時，偶爾一幀判成看得到，會把「連續 2 秒」的計時歸零。看得到要持續 1 秒以上才算數。

這三點都要做進正式版的床位模式。

## 6. 限制（簡報要誠實講）

- **樣本小**：都是同 2 隻娃娃、同一張床。危險情境影片（8116／8150）的安全片段只有 17 段、都很短（2–6 秒）且大多是仰睡正臉——這就是為什麼那兩支「0 誤報」。**6 分鐘的 IMG_8184 補上了這個缺口**：它有大量側睡，量出來誤報並不是 0（v3 2/13、床位 5/13），主因是側臉（見 §3c）。誤報樣本仍偏少（同一組娃娃），實機要在真實午睡室重量。
- **側臉是目前最大的誤報來源，也是還沒解的技術缺口**：YuNet 是正面臉偵測器，側臉分數約 0.7，床位模式的 0.8 門檻把它擋掉。娃娃只有一種臉、側臉時鼻子嘴唇其實看得到，真實嬰兒側睡更多 → 這個問題在實機只會更嚴重。
- **量不到警示延遲**：危險狀態是手擺出來的，擺的過程中手就擋住畫面，警示常在手離開前就響了。真實嬰兒翻身沒有手，延遲大約就是規則設定的 2 秒。
- **鏡頭很近**（約 1 公尺）：臉很大。天花板鏡頭看整間午睡室時臉會小很多，照片測試縮到 1080p 時口鼻檢查已經開始誤擋。
- **v4 還沒通過真實嬰兒的誤報測試**（SyRIP 6.1% → 16.6%），影片上的 97% 只代表娃娃。

## 7. 產出

- `outputs/video_eval/<影片>_timeline.png`：時間軸對照圖（標註、三種判定的每幀結果、警示中）。娃娃是自己拍的，**可以放進簡報**。
- `outputs/video_eval/<影片>_preview.mp4`：標註影片（每秒 5 幀、寬 540）。床位框紅＝警示中（預設依 v3＋床位），黃框＝找到的臉，橘框＝口鼻檢查判成被蓋住。框和警示都是系統真的跑出來的，**可以當 demo 影片的底稿**。
- `outputs/video_eval/<影片>_frames.csv`：每幀每個床位的判定和臉的分數。
